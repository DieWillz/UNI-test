# 🧵 **2. Анализ концепции `Threading` (Идентификация сообщений)**

## ✅ **Плюсы**
| Идея | Преимущества |
|------|--------------|
| **Уникальные ID** | Позволяет группировать сообщения по задачам. |
| **Категории (PLN, VIS, BRW, etc.)** | Упрощает фильтрацию и маршрутизацию. |
| **Сквозная идентификация** | Легко отслеживать цепочки действий. |

## ❌ **Проблемы и риски**
| Проблема | Описание | Уровень риска |
|----------|----------|---------------|
| **Коллизии ID** | Формат `[ДД-ЧЧ-ККК-ММСС]` зависит от времени → при одновременных задачах возможны дубли. | ⚠️ **Высокий** |
| **Закрывающие теги** | LLM может забыть закрыть тег `[/end-...]`, что нарушит парсинг. | ⚠️ **Высокий** |
| **Нагрузка на LLM** | Длинные ID увеличивают токены в промпте. | ⚠️ **Средний** |
| **Сложность парсинга** | Формат `[ДД-ЧЧ-ККК-ММСС]` требует сложной логики для извлечения данных. | ⚠️ **Средний** |

## 🔧 **Рекомендации по улучшению**
### **🔹 1. Новый формат ID**
**Предложение**:
Использовать **UUID + категория + хэш** (как в `CONCEPT_INTEGRATED_AGENCY.html`):
```python
Task ID = [UNI:{CATEGORY}:{TIMESTAMP}-{HASH}]
# Пример: [UNI:PLN:20260803-A8F2]
```
**Преимущества**:
- **Уникальность**: `TIMESTAMP` (до миллисекунд) + `HASH` (4-8 символов) гарантирует отсутствие коллизий.
- **Компактность**: Короткий формат (например, `A8F2` вместо `ДД-ЧЧ-ККК-ММСС`).
- **Легкость парсинга**: Регулярное выражение `\[UNI:(\w+):([^\]]+)\]` легко извлекает категорию и ID.

**Реализация**:
```python
import uuid
import hashlib
from datetime import datetime

def generate_task_id(category: str) -> str:
    timestamp = datetime.now().strftime("%Y%m%d-%H%M%S-%f")[:15]  # 20260803-142530-123
    hash_part = hashlib.sha256(timestamp.encode()).hexdigest()[:4]  # A8F2
    return f"[UNI:{category}:{timestamp}-{hash_part}]"
```

### **🔹 2. Отказ от закрывающих тегов**
**Проблема**: LLM может не закрыть тег `[/end-...]`.
**Решение**:
- **Не использовать закрывающие теги** — парсить ID на стороне кода.
- **Использовать разделители** (например, `---` или JSON):
  ```markdown
  [UNI:PLN:20260803-A8F2]
  Текст сообщения...
  ---
  [UNI:VIS:20260803-B1C9]
  Ответ Vision...
  ```

### **🔹 3. Оптимизация для LLM**
**Проблема**: Длинные ID увеличивают токены.
**Решение**:
- **Использовать короткие категории**:
  | Категория | Сокращение |
  |----------|------------|
  | Planner | `PLN` |
  | Vision | `VIS` |
  | Browser | `BRW` |
  | Computer | `COM` |
  | Memory | `MEM` |
  | Architecture | `ARC` |
  | Bugfix | `BUG` |
  | Voice | `VOC` |
  | XToys | `XTY` |
- **Хранить ID в метаданных**, а не в тексте сообщения (если возможно).

### **🔹 4. Автоматический парсинг**
**Реализация**:
```python
import re

def parse_task_id(text: str) -> dict | None:
    match = re.search(r"\[UNI:(\w+):([^\]]+)\]", text)
    if not match:
        return None
    category, task_id = match.groups()
    return {"category": category, "task_id": task_id}
```

# 🖱️ **3. Анализ концепции `Mouse Control` (Управление мышью)**

## ✅ **Плюсы**

|------|--------------|
| **Dual-Mode** | Разделение на `Interactive` (визуальный) и `Turbo` (быстрый). |

## ❌ **Проблемы и риски**
| Проблема | Описание | Уровень риска |
|----------|----------|---------------|
| **Замедление рутинных задач** | В `Interactive Mode` парсинг и фоновые задачи работают медленно. | ⚠️ **Высокий** |
| **Сложность реализации Easing** | Кривые Безье требуют сложных вычислений. | ⚠️ **Средний** |
| **Конфликт с Playwright** | Playwright не поддерживает плавное движение мыши. | ⚠️ **Высокий** |
| **Зависимость от Screen Capture** | `Interactive Mode` требует активного захвата экрана. | ⚠️ **Средний** |

## 🔧 **Рекомендации по улучшению**
### **🔹 1. Уточнение режимов**
**Предложение**:
| Режим | Описание | Применение |
|-------|----------|------------|
| **Interactive Mode** | Плавные движения, анимации, задержки. | Для работы с пользователем (демонстрация, отладка). |
| **Turbo Mode** | Прямые CDP/DOM-события, максимальная скорость. | Для фоновых задач (парсинг, тесты). |
| **Hybrid Mode** | Плавные движения **только для видимых пользователю действий**. | По умолчанию. |

**Реализация**:
```python
from enum import Enum

class MouseMode(Enum):
    INTERACTIVE = "interactive"  # Плавные движения + анимации
    TURBO = "turbo"               # Быстрые CDP-события
    HYBRID = "hybrid"             # Плавные движения только для видимых действий
```

### **🔹 2. Реализация Easing**
**Проблема**: Playwright не поддерживает плавное движение мыши.
**Решение**:
- **Использовать `pyautogui` для плавных движений**:
  ```python
  import pyautogui
  import time
  import math

  def smooth_move(x1, y1, x2, y2, duration=0.5):
      """Плавное движение по кривой Безье."""
      steps = 50
      for i in range(steps):
          t = i / steps
          # Кривая Безье (упрощённая)
          x = x1 + (x2 - x1) * (1 - math.cos(t * math.pi)) / 2
          y = y1 + (y2 - y1) * (1 - math.cos(t * math.pi)) / 2
          pyautogui.moveTo(x, y, _pause=False)
          time.sleep(duration / steps)
  ```
- **Для Turbo Mode**:
  ```python
  def turbo_click(x, y):
      """Мгновенный клик через Playwright."""
      page.mouse.click(x, y)
  ```

### **🔹 3. Автоматическое переключение режимов**
**Предложение**:
- **Interactive Mode**:
  - Включается, если:
    - Активен захват экрана (`Screen Capture`).
    - Пользователь наблюдает за процессом (например, через веб-интерфейс).
- **Turbo Mode**:
  - Включается, если:
    - Задача выполняется в фоне.
    - Нет активного захвата экрана.
- **Hybrid Mode**:
  - Плавные движения только для действий, видимых пользователю (например, клики в браузере).
  - Быстрые события для фоновых задач (например, парсинг DOM).

**Реализация**:
```python
class MouseController:
    def __init__(self, mode: MouseMode = MouseMode.HYBRID):
        self.mode = mode
        self.screen_capture_active = False

    def move(self, x, y, duration=0.5):
        if self.mode == MouseMode.TURBO:
            page.mouse.move(x, y)  # Playwright (быстро)
        else:
            smooth_move(x, y, duration)  # pyautogui (плавно)
```

### **🔹 4. Визуальная обратная связь**
**Предложение**:
- **Пульсация кликов**:

### **🔹 3. Автоматическое обновление шаблонов**
**Проблема**: При изменении сайта нужно вручную обновлять `SiteProfile`.
**Решение**:
- **Добавить механизм обучения**:
  - Если `Auditor` обнаруживает, что селектор не работает, он может:
    1. Попробовать найти новый селектор (через Vision).
    2. Сохранить его в `SiteProfile` (с пометкой `auto_generated: true`).
    3. Предложить пользователю подтвердить изменение.
- **Реализация**:
  ```python
  class SiteProfileUpdater:
      def __init__(self, profile_path: str):
          self.profile_path = profile_path
          self.profile = self._load_profile()

      def update_selector(self, old_selector: str, new_selector: str):
          if old_selector in self.profile["selectors"]:
              self.profile["selectors"][old_selector] = new_selector
              self.profile["auto_generated"] = True
              self._save_profile()

      def _load_profile(self) -> dict:
          with open(self.profile_path, "r", encoding="utf-8") as f:
              return json.load(f)

      def _save_profile(self):
          with open(self.profile_path, "w", encoding="utf-8") as f:
              json.dump(self.profile, f, indent=2, ensure_ascii=False)
  ```

# 🔍 **5. Анализ концепции `Status Check` (Проверка статуса)**

## ✅ **Плюсы**
| Идея | Преимущества |
|------|--------------|
| **Трёхуровневая проверка** | Vision + Browser + Computer → надёжность. |
| **Auditor** | Централизованная проверка результатов. |
| **Эскалация после 3 неудач** | Инвариант безопасности. |
| **Структурированный ответ** | Легко анализировать причины ошибок. |

## ❌ **Проблемы и риски**
| Проблема | Описание | Уровень риска |
|----------|----------|---------------|
| **Зацикливание при ошибках** | Нет чёткого правила, что делать после 3 неудач. | ⚠️ **Высокий** |
| **Сложность Auditor** | Нужно реализовать логику для всех типов проверок. | ⚠️ **Средний** |
| **Нет приоритетов проверок** | Все уровни (Vision, Browser, Computer) равнозначны. | ⚠️ **Средний** |
| **Нет кэширования результатов** | Повторные проверки одного и того же действия. | ⚠️ **Низкий** |

## 🔧 **Рекомендации по улучшению**
### **🔹 1. Чёткое правило эскалации**
**Предложение** (как в `CONCEPT_INTEGRATED_AGENCY.html`):
- **После 3 неудачных попыток**:
  - Задача переводится в статус `PAUSED_NEEDS_USER_INTERVENTION`.
  - Фиксируется **скриншот** и **логи**.
  - Уведомляется пользователь (через веб-интерфейс или консоль).
- **Реализация**:
  ```python
  class Auditor:
      MAX_RETRIES = 3

      def verify_action(self, task_id: str, action: str) -> AuditResult:
          for attempt in range(self.MAX_RETRIES):
              result = self._check_action(task_id, action)
              if result.verified:
                  return result
              time.sleep(1)  # Задержка перед повторной попыткой

          # После 3 неудач
          return AuditResult(
              task_id=task_id,
              verified=False,
              attempts_left=0,
              check_levels=result.check_levels,
              reason=f"Failed after {self.MAX_RETRIES} attempts",
              recommended_action="Manual intervention required",
              status="PAUSED_NEEDS_USER_INTERVENTION"
          )
  ```

### **🔹 2. Приоритеты проверок**
**Предложение**:
- **Уровень 1 (Быстрый)**: Browser (DOM/URL) → если успешно, не проверять Vision.
- **Уровень 2 (Средний)**: Vision (скриншот + OCR).
- **Уровень 3 (Медленный)**: Computer (окна/процессы).
- **Реализация**:
  ```python
  class StatusCollector:
      def collect_status(self, task_id: str) -> dict:
          status = {}

          # Уровень 1: Browser (быстро)
          status["browser"] = self._check_browser(task_id)
          if status["browser"] == "success":
              return status  # Не проверяем дальше

          # Уровень 2: Vision (средне)
          status["vision"] = self._check_vision(task_id)
          if status["vision"] == "success":
              return status

          # Уровень 3: Computer (медленно)
          status["computer"] = self._check_computer(task_id)
          return status
  ```

### **🔹 3. Кэширование результатов**
**Предложение**:
- Кэшировать результаты проверок для одного и того же действия в течение **N секунд**.
- **Реализация**:
  ```python
  from functools import lru_cache
  import time

  class StatusCollector:
      def __init__(self):
          self.cache = {}

      @lru_cache(maxsize=100)
      def _check_browser(self, task_id: str) -> str:
          # Логика проверки
          return "success"

      def collect_status(self, task_id: str) -> dict:
          cache_key = f"{task_id}-{int(time.time() // 10)}"  # Кэш на 10 секунд
          if cache_key in self.cache:
              return self.cache[cache_key]

          status = self._collect_status_uncached(task_id)
          self.cache[cache_key] = status
          return status
  ```

### 1. Критические баги (Необходимо исправить прямо сейчас)

**Файл `autonomous.py`:**
* **Опечатка в `re.search`:** В методе `_is_connected` вы используете `re_search` (с нижним подчеркиванием), хотя правильно — `re.search`. Это вызовет `NameError` при первой же проверке статуса XToys.
  ```python

  return bool(re_search(r"connected|disconnect|stop|включ|подключ", text, re.I))
  # Стало:
  return bool(re.search(r"connected|disconnect|stop|включ|подключ", text, re.I))
  ```

**Файл `browser_session.py`:**

### 2. Проблемы параллелизма и безопасности (Concurrency & Safety)

**Игнорирование локов в автономном режиме:**
В `event_loop.py` все инструменты вызываются через `async with self._tool_lock:`. Однако в `autonomous.py` метод `_run_tool` написан так:
```python
async def _run_tool(self, name: str, args: dict) -> ToolResult:
    """Execute a tool WITHOUT the global EventLoop lock (parallel autonomy)."""
    return await self.agent.tool_executor.execute(name, args)
```
**Проблема:** Playwright (браузер) — это библиотека с состоянием (stateful). Если `EventLoop` (например, делает скриншот) и `AutonomousController` (например, дергает слайдер XToys) одновременно попытаются обратиться к `BrowserSession`, Playwright может выбросить ошибку или кликнуть не туда. 
**Решение:** Лок (`_tool_lock`) нужно использовать **всегда**, когда вы работаете с общими ресурсами (браузер, мышь, клавиатура). Если автономный режим висит из-за долгого ответа LLM, разблокируйте лок только на время ожидания сети, но блокируйте его на время DOM-операций.

**Аварийная остановка (Emergency Stop):**
В `emergency_stop` создается таска через `asyncio.create_task(...)`. В критической ситуации (например, болевой предел) задача может встать в очередь за другими тасками и сработать с задержкой. 
**Решение:** Для аварийной остановки физических устройств лучше использовать синхронный вызов (если это возможно) или гарантию того, что таска выполняется немедленно.

### 3. Архитектурные улучшения (Refactoring)

**Файл `event_loop.py`:**
* **Монструозный `parse_direct_command`:** Этот метод состоит из огромного количества `if` и регулярок. Поддерживать его будет кошмаром. Если ИИ скажет "Открой игрушку" вместо "Включи игрушку", код сломается.
  **Решение:** Разбейте парсинг на классы-обработчики (Command Pattern) или вынесите логику в словарь синонимов. В идеале, для естественного языка нужно сильнее опираться на LLM (Tool Calling), а регуляры оставить только для жестких команд (стоп, интенсивность N).
* **Магические числа в истории:** `self._history[-8:]` и `self._history[-16:]`. Вынесите эти числа в `config.yaml` (например, `config.memory.short_term_history_size`).
* **Уязвимость `_clean_answer`:** Разбивка текста на предложения через `re.split(r"(?<=[.!?])\s+", clean)` плохо работает для русского языка (сокращения вроде "т.д.", "г.", инициалы "А.С. Пушкин" будут разрезаны). 
  **Решение:** Используйте библиотеку `nltk` (`nltk.sent_tokenize`) или просто обрезайте по лимиту символов, не пытаясь угадать границы предложений.

**Файл `browser_session.py`:**
* **Хрупкие CSS-селекторы:** 
  В `search_web` используется `li.b_algo h2 a` (это селектор Bing). В `search_images` — `a.iusc` (Bing Images) и парсинг атрибута `m` через JSON. 
  **Проблема:** Поисковики меняют верстку почти каждый месяц. Ваш код сломается при следующем апдейте Bing.
  **Решение:** 
  1. Используйте официальные API (Bing Search API, Google Custom Search JSON API), где это возможно. 
  2. Для парсинга картинок Yandex/Bing лучше использовать Playwright Accessibility Tree (дерево доступности) или抽取 `img` теги с определенными фильтрами, а не уникальные классы поисковика.
* **Обработка всплывающих окон:** В `search_images` есть попытка кликнуть "Нет, спасибо" (`decline = page.get_by_text("Нет, спасибо", exact=True)`). Это сработает только в русской локали. Лучше искать по роли кнопки или просто блокировать оверлеи через `page.add_init_script()`.

```python
import aiofiles
import asyncio

class WorkingMemory:
    def __init__(self, path: Path, persist_interval: float = 5.0):
        self._lock = asyncio.Lock()
        self._dirty = False
        self._persist_interval = persist_interval
        self._persist_task = None
    
    async def append_exchange(self, user: str, assistant: str) -> bool:
        async with self._lock:
            self.data["exchanges"].append(...)
            self._dirty = True
        self._schedule_persist()  # debounced
        return True
    
    async def _persist(self) -> None:
        async with self._lock:
            if not self._dirty:
                return
            self._dirty = False
            async with aiofiles.open(self.path, "w") as f:
                await f.write(json.dumps(self.data))
```

```python
class CapabilityPlugin(BaseModel):
    name: str
    factory: Callable[[Config], Capability]
    dependencies: list[str] = []

class PluginRegistry:
    @classmethod
    def discover(cls):
        """Auto-discover capabilities from modules."""
        for file in Path(__file__).parent.glob("*.py"):
            module = importlib.import_module(f"uni.capabilities.{file.stem}")
            if hasattr(module, "CAPABILITY_PLUGIN"):
                plugin = module.CAPABILITY_PLUGIN
                cls._plugins[plugin.name] = plugin
    
    @classmethod
    def create_all(cls, config: Config) -> CapabilityRegistry:
        registry = CapabilityRegistry()
        # topological sort по dependencies
        for plugin in cls._topological_sort():
            deps = {dep: registry.get(dep) for dep in plugin.dependencies}
            cap = plugin.factory(config, **deps)
            registry.register(cap)
        return registry
```
