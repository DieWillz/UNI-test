## 1. Чат с ИИ (`/api/chat`)

**Статус:** ✅ Работает (только текст)

**Как проверить:**
1. Откройте админку → вкладка **Chat**
2. Введите текстовое сообщение в поле ввода
3. Отправьте (Enter или кнопка)
4. **Ожидаемый результат:** Юни отвечает текстом, ответ появляется в чате

**Что НЕ работает:**
- Отправка изображений → 500 ошибка "VLM API недоступен"
- Анализ кадров с камеры через чат → та же ошибка VLM

## 2. Council / Консенсус (`/api/round/start`)

**Статус:** ⚠️ Работает с ограничениями

**Как проверить:**
1. Откройте админку → вкладка **Consensus**
2. Введите тему обсуждения
3. Выберите участников (Hermes всегда доступен)
4. Нажмите "Начать раунд"
5. **Ожидаемый результат:** SSE-поток показывает прогресс раунда, в конце — синтез мнений

**Ограничения:**
- Требует настроенных API-участников (OpenAI, Anthropic и т.д.) в `config.yaml`
- Браузерные участники требуют запущенной Playwright-сессии
- Hermes (локальная модель) работает без дополнительной конфигурации

## 3. Управление устройством Dorch (`/api/xtoys/*`)

**Статус:** ⚠️ Реализовано, требует Intiface + физическое устройство

**Как проверить:**
1. Откройте админку → вкладка **Dorch**
2. **Ручной режим:** Перейдите на вкладку "Manual", установите ползунок интенсивности
   - Без подключённого Intlace → ответ `{"mode": "emulated", "message": "..."}`
   - С подключённым Intiface → команда отправляется на устройство
3. **Паттерны:** Вкладка "Patterns" → выберите паттерн (ramp, climb, pulse, wave, hold, cooldown)
   - Требует подключённого Intiface
4. **Плейлист:** Вкладка "Playlist" → загрузите список паттернов
5. **Экстренная остановка:** Кнопка "STOP" → `/api/xtoys/emergency-stop`
6. **Автономный режим:** Кнопка "Автоматический режим" → `/api/autonomous/start`

**Важно:**
- Максимальная интенсивность ограничена `config.capabilities.xtoys.max_intensity` (по умолчанию 50%)
- `verified_physical=false` — физическое движение не подтверждается автоматически
- Emergency STOP пишет `STOP.txt` в корень проекта

## 5. Речь: TTS (`/api/tts`)

**Статус:** ✅ Работает (локальный Silero)

**Как проверить:**
1. Откройте админку → вкладка **Settings** → раздел TTS
2. Выберите провайдера: **Silero** → голос **Xenia**
3. Введите текст: "Привет. Это проверка голоса Юни."
4. Нажмите "Тест" (`/api/tts/test`)
5. **Ожидаемый результат:** Браузер воспроизводит аудио (Silero xenia — женский голос)

**Поддерживаемые провайдеры:**
- `silero` (локально, xenia/kseniya/baya/eugene/aidar)
- `piper` (локально, ru_RU-irina-medium.onnx)
- `browser` (системный голос браузера)
- `xtts` / `fish` (внешние HTTP-сервисы через env vars)
- `qwen_vc` (клонирование голоса через Gradio)

## 6. Речь: STT (`/api/stt/listen`)

**Статус:** ⚠️ Работает с ограничениями

**Как проверить:**
1. Откройте админку → вкладка **Logs** или **Bridge**
2. Нажмите кнопку микрофона (если есть в UI)
3. Проверьте API напрямую: `POST /api/stt/listen` с параметром `wait_seconds`
4. **Ожидаемый результат:** Возвращает распознанный текст или ошибку 503, если Whisper не установлен

**Ограничения:**
- Требует `faster-whisper` для локального распознавания
- Первый вызов занимает ~7 секунд на загрузку модели

## 7. Автономный режим (`/api/autonomous/*`)

**Статус:** ⚠️ Реализован, требует активной конфигурации

**Как проверить:**
1. В `config.yaml` включите `autonomous.enabled: true`
2. Откройте админку → вкладка **Auto**
3. Нажмите "Запустить автономный режим"
4. **Ожидаемый результат:** Юни начинает самостоятельно генерировать реплики и управлять устройством

**Проверка статуса:**
- `GET /api/chat/status` — показывает фазу, цель, текущую интенсивность

## 8. Админка и мониторинг (`/api/admin/*`)

**Статус:** ✅ Работает

**Как проверить:**
1. Откройте админку → вкладка **Overview**
2. **Stack** (`/api/admin/stack`): версия Python, путь к проекту, статус модулей
3. **HW** (`/api/admin/hw`): информация о CPU, RAM, дисках, GPU
4. **Git** (`/api/admin/git`): статус ветки, коммиты, dirty files
5. **Dev** (`/api/admin/dev`): dev-утилиты
6. **Agents** (`/api/admin/agents`): статус агентов
7. **Stats** (`/api/admin/stats`): метрики
8. **Reports** (`/api/admin/reports`): список отчётов

**Админ-действия** (`POST /api/admin/actions`):
- `run_pytest` — запустить тесты
- `run_selftest` — запустить самотест
- `run_arch_check` — проверить архитектуру
- `create_stop_txt` — создать STOP.txt
- `set_ui_variant` — сменить UI
- `set_role` — сменить роль
- `set_consent` — установить согласие
- `demo_mouse` — демо мыши
- `vision_capture` — захват экрана
- `show_overlay` — показать оверлей
