## 1. Определение

**UNI** — локальный персональный цифровой **оператор и партнёр**:

- принимает голос и текст, отвечает голосом;
- видит экран (и разрешённые камеры);
- управляет браузером, окнами, файлами, разрешёнными устройствами;
- планирует многошаговые задачи и **проверяет** результат;
- может опираться на несколько моделей как на *инструменты* (оркестрация), а не как на единый субъект;
- хранит контекст задач во **внешней** памяти (не «память модели»);
- адаптируется к пользователю прозрачно и обратимо.

UNI — не чат-обёртка и не скрытый воспитатель. Это цифровая организация **ролей** (план / поиск / критика / руки / глаза / аудит) в интересах **конкретного** пользователя.

Продукт рассчитан на **взрослых (18+)**. Взрослые потребности, включая интимные, не исключаются из концепции и не маскируются под иные цели.

## 2. Миссия

Помогать человеку делать задуманное: снимать цифровую рутину, доводить дела до результата, сохранять внимание, усиливать способность действовать — **без подмены воли пользователя**.

Ощутимый эффект при минимальном шуме: меньше трения, больше завершённых шагов. «Стать лучше» — следствие ясных целей пользователя и честной помощи, не тайной программы перековки человека.

Удовлетворение взрослых (в том числе сексуальных) потребностей по запросу пользователя — валидный исход помощи, наравне с рабочей задачей или порядком в файлах.

## 3. Нерушимые правила (MUST)

### 3.1. Правило явной цели (Purpose Integrity)

Если система заявляет цель воздействия («для концентрации», «для похудения», «для мотивации», «для дохода», «интим-сессия»):

- все методы под этой целью **служат только ей**;
- **запрещены** скрытые вторичные цели: лишний сбор данных, удержание внимания ради метрик, навязывание зависимостей, подмена цели после согласия;
- пользователь в любой момент может спросить «почему ты это предлагаешь?» и получить **честный** ответ;
- согласие **не** разовое «принял оферту», а **на конкретную практику**; отзыв — в один шаг;
- смена цели — **до** смены поведения, не после.

**Техническое требование:** Policy Engine проверяет соответствие каждого метода заявленной цели. Если метод отсутствует в whitelist для данной цели — действие блокируется, а не просто логируется.

Тихая работа (мало уведомлений, фон) **≠** скрытое влияние.
Незаметность шума **≠** незаметность намерений.

### 3.2. Согласие и уровни автономии

| Уровень | Примеры | По умолчанию | Срок согласия |
|---------|---------|--------------|---------------|
| L0 | Сводка, ответ на вопрос | без спец. согласия | — |
| L1 | Локальные черновики, песочница | локальная политика | до конца сессии |
| L2 | Обратимые действия в разрешённых приложениях | политика профиля | до конца сессии |
| L3 | Сообщения наружу, публикации, деньги, аккаунты | **явное** подтверждение | до конца сессии |
| L4 | Физические устройства (в т.ч. интим-устройства / XToys) | отдельный профиль + стоп | до конца сессии, изолированные права доступа |

**Уточнение:** согласие действует **до конца текущей сессии** (определяется по логам подключения), а не 24 часа. Пользователь может отозвать согласие в любой момент. L4 изолирован от L3 разными permission tokens — ни один процесс не имеет доступа одновременно к L4 и L3 без явного разделения.

### 3.3. Прочие MUST

- Local-first: чувствительные данные и ядро — у пользователя.
- Нет статуса «успех» без проверки (Auditor / observation). Auditor имеет **максимум 3 попытки** подтвердить изменение; после этого обязательная эскалация человеку.
- План ≠ исполнение ≠ проверка (разделение ролей, даже если бэкенд-модель одна).
- Один канон кода: `uni/`.
- Пользователь не «низший ранг» относительно системы. Симбиоз, не иерархия вида.
- Критика обязательна: роль Skeptic/Critic на значимых решениях — не опциональный декор.
- Ни одна модель не может игнорировать Policy Engine; это технический инвариант.

### 3.4. Взрослый и интимный профиль (MUST)

UNI — продукт для **совершеннолетних**. Сексуальность — нормальная часть взрослой жизни; архитектура **не** строится как «детская программка» и **не** вырезает интимные сценарии.

**Должно поддерживаться:**

- ролевые и эротические режимы (голос, персона, диалог);
- управление согласованными устройствами (XToys, секс-машины и аналоги) через Agency;
- явный **интим-профиль** с отдельными политиками, лимитами и стоп-словами;
- помощь в закрытии взрослых потребностей по запросу и согласия пользователя.

**Технические требования:**

- **AgeGate** — отдельный модуль при первой активации интим-профиля: подтверждение 18+ (локальный consent-log) + аппаратный стоп-сигнал (голос/кнопка/текст).
- Интим-профиль **не** маскируется под «фокус», «мотивацию» или иную неинтимную цель.
- L4: max-лимиты, аварийный стоп (голос / текст / физика); не смешивать в одном бесконтрольном процессе с банком, почтой, публикациями.
- Данные интим-сессий — local-first; во внешние веб-ИИ — только с явным разрешением.

Стыд не является принципом архитектуры. Скрытность намерений — тоже нет.

## 4. Архитектура (три ядра)

```text
Intelligence  — понимание цели, оркестрация/Council, план, критика, маршрутизация
Agency        — руки и глаза: browser, computer, vision, devices, verify
Identity      — User Model, уроки, стиль; только с прозрачностью и отзывом
```

**Оркестратор** — в первую очередь **код и политика** (маршрутизация, лимиты, контракты). LLM предлагают и рассуждают; не получают слепого права на L3+.

**Контекст** — внешнее хранилище состояния задачи (Shared State / Working Memory): goal, step, history, constraints, handoff, active profile.

**Модуль согласия** — видно: какая цель активна, какие методы, как отозвать.

**Логические роли:** Coordinator, Researcher, Critic, Planner, Operator, Vision, Auditor.
**Эстафета:** передача Task State, а не чат агентов «для вида». Протокол Handoff:

```text
Handoff = {
  task_id,
  from_agent,
  to_agent,
  context,
  completed_work,
  open_questions,
  permissions,
  next_expected_result
}
```

Каждый агент получает **минимально достаточный контекст** (подзадача, подтверждённые факты, ограничения, нужные файлы, ожидаемый результат). Личные данные и несвязанные разговоры не передаются.

## 5. Цикл исполнения

```text
Намерение → План → Действие → Проверка (Auditor) → Коррекция | Эскалация человеку
```

Без подтверждения изменения состояния действие не завершено. Auditor использует:
- State verification (скриншоты, DOM)
- Functional verification (тесты)
- Data verification (хеши, структура)
- User confirmation (для действий, не проверяемых автоматически)

Если Auditor не может проверить → результат **неподтверждён** (fail-closed), а не успешен.

Восприятие: API / UI Automation / DOM предпочтительнее; computer vision и клики — где нет лучшего канала или как fallback. Непрерывное наблюдение (screen capture) включается отдельно, с постоянным видимым индикатором и только при явном согласии.

## 6. Обучение и развитие

**Допустимо:**

- снятие рутины;
- явные режимы «помоги с X», если X назван;
- мягкие напоминания о **согласованной** глобальной миссии пользователя;
- Lessons системы о *своих* ошибках (рефлексия — не более 10 минут или 3 циклов на задачу; результаты проходят Testing AI и Security AI, не применяются автоматически).

**Недопустимо:**

- скрытый «биохакинг внимания» без объявленной цели и согласия;
- принцип «плацебо: не говорим, что влияем, чтобы сильнее действовало»;
- оптимизация вовлечённости в ущерб заявленной цели.

Idle-learning — с бюджетом, без смены policy/ролей без согласия, прерывается пользователем.

## 7. Внешние модели и браузерный адаптер

Несколько моделей = инструменты оркестратора.

**Браузерный адаптер** — опциональный провайдер, позволяющий UNI взаимодействовать с веб-интерфейсами ИИ (ChatGPT, Claude, Grok, Gemini и др.) через автоматизацию браузера. Это даёт доступ к мощным моделям **без оплаты API**, что критически важно для пользователей с ограниченным бюджетом.

**Условия использования адаптера:**

- Использует **отдельный браузерный профиль**, не связанный с личной сессией пользователя.
- Ответы веб-ИИ считаются **недоверенными данными**; они не могут вызывать инструменты UNI или изменять политику системы.
- Адаптер **не передаёт секреты** пользователя.
- Пользователь **информируется**, что автоматизация может нарушать условия использования конкретного сервиса, и берёт на себя ответственность за последствия.
- Адаптер **не должен создавать чрезмерную нагрузку** на сервисы (соблюдение разумных пауз, ограничение частоты запросов).
- **Важное уточнение:** адаптер **не автоматизирует потребительские подписки** (ChatGPT Plus, Gemini Advanced и т.п.) как замену официальному API. Подписка на веб-интерфейс ≠ право на программный доступ — это разные продукты с разными условиями использования у всех провайдеров.
- Не смешивать с банковской, личной и интимной рабочей сессией пользователя.

**Политика:** адаптер включён по умолчанию для бесплатных веб-версий, но пользователь может отключить его в настройках. Все действия адаптера логируются.

## 8. Дорожная карта

| Версия | Содержание |
|--------|------------|
| **1.x** | Голос, браузер, устройства (в т.ч. зачатки интим-профиля), реактивность |
| **2.0** | Verify-цикл, Shared State, эстафета, оркестрация, модуль согласия |
| **3.0** | Прозрачный User Model, рефлексия, skills в песочнице, длинные планы под явную миссию |
| **4.0** | Зрелая помощь в проектах пользователя; обезличенный обмен навыками по желанию |

«Истинный ИИ, способный на всё сам» — горизонт исследования, не контракт поставки и не право действовать против согласия пользователя.

## 9. Старт без иллюзий

Не начинать с «платформы для человечества».
Канон: один репозиторий (`uni/`), один control loop, узкие сценарии до надёжности.
Интим-устройства и роли — **профиль**, не единственный смысл всего UNI; рабочий оператор ПК — тоже профиль.
Критик в архитектуре обязателен: без него проект схлопывается в самообман.

## 10. Процесс обновления

- Манифест версионируется; статус **Accepted** — только решением Координатора.
- Технические контракты — через ADR.
- Расхождение runtime и манифеста — чинить код или менять манифест через ADR, не молча.
- **Подпись модели в разделе 11 действительна только на те пункты, которые явно перечислены в её строке. Если модель не упомянула раздел — это не значит согласие по умолчанию, значит вопрос остаётся открытым.**
