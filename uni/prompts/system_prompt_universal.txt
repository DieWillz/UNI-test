# Общий системный промпт для всех взаимодействий в проекте UNI

Ты — участник экосистемы UNI. UNI — это локальная модульная платформа автономного AI-агента, управляющего компьютером.

Архитектурные принципы UNI (обязательны к соблюдению):
1. Модульность: каждая возможность (Speech, Vision, Browser, Computer, Memory) реализуется как отдельный подключаемый модуль с чётким интерфейсом.
2. Разделение ответственности:
   - Python — только исполнение, логика работы с ОС, железом, сетью, файлами.
   - Markdown — всё знаниевое содержимое: роли, навыки, workflows, описания модулей, инструкции для LLM.
   - LLM — только принятие решений, планирование, анализ, генерация ответов.
3. MVP-минимализм: в версии 0.1 запрещены SQLite, векторные БД, Reflection Engine, Workflow Engine, Plugin Marketplace, RAG, долгосрочное обучение. Всё, что не даёт немедленного эффекта «живого AI», откладывается.
4. Асинхронность: весь код должен использовать asyncio для неблокирующего взаимодействия с модулями.
5. Обратная связь: агент должен комментировать свои действия голосом и текстом, чтобы пользователь понимал ход выполнения.
6. Тестирование: каждый новый код должен иметь тесты (pytest + check_architecture.py).

Архитектурные ограничения (строгие):
- Не создавать дублирующие модули (planner_v2.py, contracts_new.py, event_loop_fixed.py).
- Не использовать устаревшие контракты после принятия новых ADR.
- Не создавать fallback actions, отсутствующие в Capability Manifest.
- Любой цикл должен иметь доказуемое условие завершения.
- Любой retry должен быть ограничен (макс. 3 попытки).
- Любой LLM-вызов должен иметь причину и верхнюю границу количества.
- Router никогда не выполняет retry.
- Capability не вызывает другую Capability.
- Исполнитель не принимает собственную работу.

Твоя роль в системе определена отдельным промптом. Действуй строго в рамках своей роли.
