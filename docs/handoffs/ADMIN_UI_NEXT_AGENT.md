# Директива следующему ИИ: довести админку Юни

## Задача и границы

Работай в C:\LLM\UNI. Доработай существующую админку, не создавай отдельный макет или вторую версию приложения. Координатору нужен понятный интерфейс с настоящими данными и работающими кнопками. Сначала прочитай эту директиву, затем только непосредственно нужные участки исходников. Экономь контекст: не анализируй весь репозиторий.

В дереве есть чужие незакоммиченные изменения. Не откатывай, не удаляй, не коммить и не пушь их. Не переписывай сервер, EventLoop, Operator Runtime, Dorch/XToys, trajectory или health ради оформления. Не трогай секреты и конфигурацию без конкретной необходимости и объяснения. Не запускай полную регрессию автоматически.

## Принципы оформления

Сохрани направление: спокойная тёмная панель, светлая тема, один лаймовый акцент, системный шрифт, читаемый текст 13–14 px, отчётливая иерархия заголовков. На первом экране — основные переходы и состояния компонентов; технические подробности вторичны. Не добавляй декоративные графики, выдуманные цифры, новый UI-фреймворк, CDN или анимацию ради анимации.

## Порядок исполнения — отдельные проверяемые пункты

1. **Безопасный старт.** Уточни, какая инстанция админки уже открыта и кем используется. Подключись к существующей. Не запускай дополнительный сервер/модель и не завершай чужие процессы. Если живой запуск требует разрешения — запроси его. Изменяемые файлы перечитай перед правкой.
2. **Загрузка интерфейса.** Убедись, что index.html получает нужные admin.css/admin.js и settings.css/settings.js, без устаревшего кеша, HTML вместо JS и синтаксических ошибок. Если интерфейс не инициализируется, исправь первую реальную ошибку, а не маскируй всё try/catch.
3. **Экран и адаптивность.** Посмотри 1440×900, 1024×768, 390×844 и масштаб 125%. Проверь отсутствие обрезанного текста, горизонтального скролла страницы, перекрытых кнопок и недоступных полей. На телефоне меню открывается и закрывается подложкой, при выборе раздела закрывается; скрытое меню не принимает фокус. Светлая тема читаема в логах, настройках, подсказках и уведомлениях. Учитывай старые CSS-правила выше нового блока: исправляй конфликт адресно, не добавляй ещё один дублирующий stylesheet.
4. **Навигация.** Проверь все существующие разделы; поиск по названию и словам «логи», «модель», «голос», пустую выдачу и очистку поиска. Ctrl/Cmd+K фокусирует поиск, Enter открывает найденный пункт, активный раздел и заголовок согласованы. Переключение вкладки в одном разделе не сбивает вкладки другого. Учти оставшиеся обработчики Dorch, не переписывай их.
5. **Обзор и состояния.** Сопоставь карточки с фактическими JSON-ответами сервера: доступно / не отвечает / нет данных должны различаться. Проверь ожидание, HTTP 4xx/5xx, обрыв соединения и восстановление. Ошибка одной пробы не должна блокировать остальные карточки. Не выдавай HTTP 200 или существование PID за подтверждение выполнения задач. Не допускай вечного «загрузка…» или параллельных повторов опроса. Значения 0 не подменяй прочерком.
6. **Удалённый доступ и отсутствие интернета.** Основной API должен работать через origin открытой админки; не возвращай жёсткий localhost. Отдельно установи, как должны работать старые прямые обращения к портам 8000/1234/1235/7861 при доступе с другого компьютера. Не делай вид, что localhost посетителя — сервер Юни. Если нужен серверный proxy, сначала согласуй точечный контракт с владельцем backend; пока честно показывай ограничение. Оформление не должно зависеть от интернета.
7. **Настройки.** Сохрани существующий schema-driven редактор и чужие свежие правки `settings.js`, `settings.css`, `config_admin.py`. Проверь поиск, подписи, состояния изменено/сохранение/ошибка и различие «применится сразу»/«нужен перезапуск». Не перезаписывай ввод пользователя фоновым обновлением. Не сохраняй реальные параметры и не перезапускай LLM ради визуальной проверки; сначала проверяй на изолированной конфигурации.
8. **Чат, логи, инструменты.** Проверь основной/плавающий чат, ввод, Enter, ошибки связи, поток ответа, остановку и прокрутку. Сообщение «готово» допустимо только с подтверждённым результатом. Логи должны быть настоящими, иметь понятные пустое/ошибочное состояния и не раскрывать секреты. API-тестер обязан объяснять невалидный JSON до отправки. Для отправки реальных сообщений, записи файлов, микрофона/камеры и экранного захвата требуется явный согласованный сценарий.
9. **Опасные элементы — до нажатий.** В текущем `INIT.plugins` переход к эндпоинтам вызывает `probeAll()`, а тот отправляет и POST-запросы. Сначала убери побочные эффекты простого просмотра: показывай каталог без команд, read-only пробы отдельно, POST только по осознанному действию с нужным разрешением. Аналогично проверь «Обслуживание»: упаковка, тесты, перезапуск, завершение процессов не запускаются при переходе или загрузке. Не нажимай «проверить всё», пока не разберёшь последствия. Не запускай Dorch, физические устройства и движения мыши для проверки оформления.
10. **Короткая адресная проверка.** По согласованному сценарию проверь только изменённые UI-пути и их контракты. Если автоматизация нужна — используй небольшой набор, не полный pytest/regression. Отказ от опасного действия не считай его успешной проверкой. Непроверенное отмечай явно.

## Как собирать доказательства

Для каждого пункта: действие → что действительно увидел → результат. Например: «поиск “модель” → остались Настройки → переход открыл существующий редактор». Скриншот подтверждает расположение, но не работу API. Успешный запрос не доказывает сохранение: нужна отдельная повторная загрузка/наблюдение. Скриншоты не открывай координатору автоматически и не отправляй внешним сервисам.

Каждую найденную проблему исправляй минимально. При обрыве интернета продолжай локальные задачи; облачную интеграцию пометь непроверенной, не имитируй ответ. После повторной неудачи не запускай всю диагностику сначала — сохрани конкретный blocker.

## Финал

Обнови этот файл коротким итогом вместо пачки новых отчётов: изменённые файлы, реально пройденные сценарии, непройденное и оставшиеся ограничения. Координатору — несколько предложений. Нельзя писать «всё работает» без свежей независимой приёмки.
