# UNI — локальный персональный AI-оператор

UNI — экспериментальный локальный AI-агент для Windows, который объединяет
голосовой и текстовый диалог, управление браузером и приложениями, компьютерное
зрение, память и совет из нескольких моделей ИИ.

Проект развивается в сторону персонального цифрового оператора: пользователь
формулирует цель обычным языком, а UNI помогает понять её, выполнить доступные
действия на компьютере, проверить результат и сохранить понятный журнал работы.

> **Статус:** активно разрабатываемый MVP. Реактивный интерактивный режим уже
> работает; полноценное автономное планирование и автоматическая разработка
> находятся в процессе интеграции.

## Что уже реализовано

- одновременный текстовый и голосовой ввод;
- русское распознавание речи и озвучивание ответов;
- подключение локальных моделей через OpenAI-совместимый API LM Studio;
- автоматический выбор текстовой модели, загруженной в LM Studio;
- управление браузером, веб-поиск и поиск изображений;
- анализ вкладки и экрана через подключаемую Vision-модель;
- управление XToys через браузерный интерфейс с ограничениями интенсивности;
- камера с обязательным голосовым уведомлением перед просмотром;
- локальная память диалога и журналирование сессий;
- роли UNI в Markdown-файлах;
- UNI Council — веб-консоль для передачи одной задачи нескольким ИИ и сбора
  ответов в единый отчёт;
- API- и браузерные адаптеры для участников Council;
- отдельный браузерный профиль для автоматизации веб-ИИ;
- архитектурные ADR, реестр задач и автоматическая проверка зависимостей.

## Быстрый запуск

### Веб-консоль разработки

На Windows запустите двойным щелчком:

```text
Запустить UNI WebUI.bat
```

После запуска откроется:

```text
http://127.0.0.1:8787/
```

Альтернативный запуск из терминала:

```powershell
py -3 -m uni --webui
```

### Интерактивная UNI

```powershell
# Текст и микрофон в одной сессии
py -3 -m uni

# Только текст
py -3 -m uni --text

# Только голос
py -3 -m uni --voice

# Одна команда
py -3 -m uni "найди в интернете породы самых крупных собак"
```

Все параметры:

```powershell
py -3 -m uni --help
```

## Установка для разработки

Требуется Python 3.11 или новее; основная локальная среда проекта использует
Python 3.12.

```powershell
py -3 -m pip install -r requirements.txt
py -3 -m playwright install chromium
```

Для свободного диалога запустите Local Server в LM Studio. В `config.yaml`
оставьте:

```yaml
brain:
  base_url: http://localhost:1234/v1
  model: auto
```

UNI выберет модель, которая сейчас загружена в LM Studio. Vision может работать
через отдельную модель или локальный Gradio-сервер.

## Архитектура

Каноническая реализация находится только в каталоге [`uni/`](uni/).

```text
Пользователь
    ↓
Agent / EventLoop
    ↓
LLM + детерминированные команды
    ↓
инструменты и capability-адаптеры
    ↓
браузер / Windows / Vision / речь / память / XToys
```

Основные каталоги:

```text
uni/                 основной Python-пакет
uni/capabilities/    возможности агента
uni/council/         координация нескольких ИИ
uni/webui/           веб-интерфейс Council
uni/roles/           редактируемые роли
tests/               автоматические тесты
docs/decisions/      архитектурные решения (ADR)
.uni-dev/tasks.yaml  реестр задач разработки
```

Архитектурные правила описаны в [ARCHITECTURE.md](ARCHITECTURE.md) и
[AGENTS.md](AGENTS.md). Текущее состояние сборки — в
[BUILD_STATUS.md](BUILD_STATUS.md).

## Проверка изменений

```powershell
py -3 -m pytest
py -3 scripts/check_architecture.py
```

Изменение не считается готовым, если тесты или архитектурная проверка завершаются
с ошибкой.

## Конфигурация и секреты

Рабочий `config.yaml` хранится локально и не должен попадать в Git. Не публикуйте:

- API-ключи и токены;
- пароли и данные авторизации;
- браузерные профили;
- локальную память, логи и снимки экрана.

Для публичных примеров используйте конфигурацию без секретов.

## Ограничения MVP

- Planner, TaskQueue, Router и единый `AgentContext` ещё не объединены в полностью
  автономный многошаговый контур.
- Веб-интерфейсы сторонних ИИ могут меняться и ломать браузерные селекторы.
- Результат клика или команды не считается подтверждённым без повторного
  наблюдения или явной проверки.
- Действия с устройствами, камерой, сообщениями и внешними аккаунтами должны
  оставаться прозрачными и ограниченными настройками пользователя.
- Внешние ответы ИИ считаются предложениями, а не доверенными командами.

## Видение проекта

UNI должна стать локальным центром управления цифровой жизнью пользователя:
понимать долгосрочные цели, передавать подзадачи подходящим моделям, работать в
любых приложениях через API или компьютерное зрение, учиться на проверенных
результатах и помогать человеку без лишней рутины. При этом пользователь должен
видеть, что именно делает система, иметь возможность остановить её и сохранять
контроль над аккаунтами, данными, деньгами и физическими устройствами.
